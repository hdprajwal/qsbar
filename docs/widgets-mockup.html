qsbar — six new widgets

Design mockup, not an implementation. Colours are the live matugen palette for ~/wallpapers/black.jpg; bar size, gap, padding, margin and the 4 px corner radius are read from your config.json and hyprctl. Interface names and addresses are your real ones. Everything else is plausible sample data.

The bar follows the desktop's GTK color-scheme, so both schemes are real states.

1 — World clock

01 World clock type: "calendar"

Not a new widget. The existing calendar panel grows a third block under the month grid. The bar slot is untouched, so nothing about your current layout changes.

Calendar panel — before / after

Config

{
  "type": "calendar",
  "format": "HH:mm",
  // new — omit for no world clock
  "worldClock": [
    "America/Los_Angeles",
    "Europe/London",
    "Asia/Tokyo"
  ],
  "worldClockFormat": "HH:mm"
}

Notes

  • Offsets are relative to you. "London −4:30" is more useful than "UTC+1" when you are deciding whether to send a message.
  • Day marker only when it differs. Tokyo shows Fri; London shows nothing. No noise for the common case.
  • Sun glyph is a rough day/night read, computed from the zone's local hour — no location lookup.
  • Your own zone is listed and marked local, so the column lines up and you can compare without arithmetic.
  • Zones added in the panel persist to state.json, never to config.json — same rule the control centre's pins follow.
  • Qt has the tz database via Intl/Qt.formatDateTime, so no new dependency and DST is handled for free.
Check this: should the panel-added zones and the config.json list merge, or should the presence of a config list make the panel read-only? Merging is friendlier; read-only is more predictable.

2 — AI usage

02 AI usage type: "aiUsage"

Tabbed. All is the at-a-glance view — one line per provider, both limit windows side by side. Each provider then has its own tab with seven days of history. Providers are addressed by their mark rather than their name, so the row stays narrow enough for two gauges.

Bar states

62%
Default — the tightest window across all providers, with that provider's mark.
93%
Codex weekly is the binding constraint today, so the bar switches to it and turns urgent.
62% · 93%
barSource: "all" — every provider in the bar. Widest option, ~150 px.
—
Nothing in the current window.

Panel — click the tabs

Config

{
  "type": "aiUsage",
  "interval": 60,
  "tools": ["claude", "codex",
             "opencode", "gemini"],
  // which number the bar shows:
  // "max" | "claude" | "all"
  "barSource": "max",
  "warnThreshold": 85,
  "defaultTab": "all",
  "historyDays": 7,
  // only needed for inferred limits
  "claudeCeiling": {
    "fiveHour": 88000000,
    "weekly": 1200000000
  }
}

Which numbers are real

  • Codex — exact. Every token_count event in its rollout logs carries a rate_limits object: used_percent, window_minutes (300 and 10080), resets_at, plan_type, even a credit balance. Confirmed on your machine — 2,874 five-hour records and 4,103 weekly ones. Nothing to infer.
  • Claude — inferred. Nothing in ~/.claude reports quota. Percentages come from summing tokens in the window against claudeCeiling, so they drift. The panel says so in its footnote rather than presenting them as fact.
  • opencode — usage only. Its message table has per-message tokens and cost with timestamps, which is all the chart needs. Its account tables are empty, so there is no limit to show.
  • Gemini — requests, not tokens. Its quota is counted in requests, so the chart and the gauge both use that unit.

Notes

  • Today's bar is hatched because the day is not over. A solid short bar would read as a quiet day rather than a partial one.
  • The All tab sorts by pressure, not alphabetically, so whatever is about to run out is at the top.
  • Marks ship as SVGs in the widget directory, the way Widgets/Tailscale/tailscale.svg already does. Claude and Gemini keep their brand colour; Codex and opencode are monochrome and recolour to the foreground, so they survive the light scheme.
  • A provider with no data at all is dropped from the tab strip entirely rather than shown empty.
  • The tab you last used persists to state.json.
Worth deciding: the bar defaults to "max" — the single tightest window across all four, wearing that provider's mark. It means the icon in your bar changes as the binding constraint moves, which is informative but also a bit restless. "claude" pins it to one provider if you would rather it sat still.
Claude's ceiling is a guess you have to supply. claudeCeiling defaults to a Max 20× figure. If you would rather not tune a number that Anthropic can change without telling you, say so and I will drop Claude's percentages and show window token totals instead — the Codex gauges stay exact either way.

3 — Screen time

03 Screen time type: "screenTime"

You asked not to build this if it needs another app running. It does not. qsbar is already a long-lived process with a Hyprland IPC connection — the same one activeWindow uses. Screen time subscribes to the same event stream, accumulates per-app seconds in memory, and flushes a rollup to disk periodically. Nothing new starts at boot.

Bar states

hourglass 4h 12m
Default — total active time since midnight.
hourglass Ghostty 1h 48m
show: "current" — the app in front and its time today.
hourglass
show: "icon" — 90 px back if the bar is tight.
hourglass 0m
Just after midnight, or first run.

Panel

Config

{
  "type": "screenTime",
  // "total" | "current" | "icon"
  "show": "total",
  "maxApps": 5,
  // seconds with no input before
  // the clock stops
  "idleAfter": 120,
  "ignore": ["hyprlock"]
}

Notes

  • No daemon. Hyprland's activewindow socket event is already subscribed for the activeWindow widget — this reuses the connection.
  • Idle stops the clock. Without it, walking away for lunch reads as an hour of Ghostty. Uses the same idle source as idleInhibitor.
  • Flush on a timer and on exit, to ~/.config/qsbar/screentime.json. Losing a minute to a crash is fine; losing the day is not.
  • Apps are grouped by Hyprland class, so every Ghostty window is one row.
  • hyprlock ignored by default — a locked screen is not screen time.
Two things this cannot do, and the panel should say so rather than quietly lie: it only counts while qsbar is running, and a fresh install shows a small number for the first day. The footnote in the panel is doing that work.

4 — IP indicator

04 IP indicator type: "ip"

Local only, as you chose. Nothing is fetched, nothing leaves the machine — it reads ip -j addr and ip -j route, which is instant and free. Addresses below are your real ones.

Bar states

lan 10.0.0.95
Default — the address on the route-carrying interface.
lan wlan0 10.0.0.95
showInterface: true.
vpn_lock 100.65.16.12
prefer: "vpn" — accent while a tunnel carries the default route.
lan offline
No default route at all.

Panel

Config

{
  "type": "ip",
  "interval": 10,
  // "default" | "vpn" | "wlan0"
  "prefer": "default",
  "showInterface": false,
  "showDown": true,
  "hide": ["lo"]
}

Notes

  • No polling needed, really. ip monitor address streams changes, so the widget can be event-driven and interval is just a safety net.
  • "Active" means carries a route, not merely UP. docker0 being up on an idle machine is not what you want in the bar.
  • lo hidden by default. 127.0.0.1 in a bar is decoration.
  • Bridge names are truncated — br-85b01f1b74d7 would blow the panel width and the tail carries no meaning.
  • IPv6 is deliberately out of scope for v1. A /64 does not fit a bar slot; happy to add it as a panel-only section if you want it.
Overlap worth naming: you already run the tailscale widget, which knows the tailnet address. Two widgets showing 100.65.16.12 is redundant. Options — drop the tailnet row here, or let prefer: "vpn" be the way you pick which one owns it.

5 — Screenshot

05 Screenshot type: "screenshot"

check grim, slurp, wl-copy — all already installed
Copies to the clipboard and saves a timestamped file, then notifies with a thumbnail. No new packages.

Bar states

screenshot_region
Idle. Left click opens the menu; middle click takes a region shot directly.
screenshot_region
Menu open — selected fill, same as every other qsbar panel owner.
timer_3
Counting down a delayed shot. Click again to cancel.

Menu

Config

{
  "type": "screenshot",
  "dir": "~/Pictures/Screenshots",
  "filename": "yyyy-MM-dd_HH-mm-ss",
  "copy": true,
  "save": true,
  "notify": true,
  // left click = menu,
  // middle click = straight to this
  "quickAction": "region",
  // optional, none installed today
  "editor": ""
}

Notes

  • Region is grim -g "$(slurp)". Window is the same, with slurp fed the window boxes from hyprctl clients so it snaps instead of freehand.
  • Both toggles off is refused. A screenshot that goes nowhere is a bug, so the second one you turn off flips the other back on.
  • The panel closes before the capture. Otherwise the menu is in the shot — the classic bug in every widget of this kind.
  • editor is left empty because neither satty nor swappy is installed. Set it and the menu grows an "Annotate" entry; leave it and nothing appears.
  • Toggles persist to state.json, so your last choice survives a restart.

6 — Screen recorder

06 Screen recorder type: "screenRecord"

warning needs wl-screenrec — not installed yet (AUR)
Hardware VA-API encoding, so recording a 4K output does not cost you a core. The widget hides itself entirely if the binary is missing, rather than offering a button that fails.

Bar states

screen_record
Idle.
01:24
Recording. Urgent colour, pulsing dot, elapsed time. Click to stop.
pause 03:11
Paused. Dimmed, dot stops pulsing, timer holds.
timer_3
Countdown before recording starts.

Menu

Config

{
  "type": "screenRecord",
  "dir": "~/Videos/Recordings",
  "backend": "wl-screenrec",
  "audio": true,
  "microphone": false,
  "cursor": true,
  "codec": "h264",
  "quickAction": "region",
  "alwaysShow": false
}

Notes

  • Recording survives a qsbar reload. The child is spawned detached and its PID written to state.json, so hot-reloading the shell mid-recording does not kill the take. On start-up the widget adopts a live PID it finds.
  • Stop is SIGINT, not SIGKILL — wl-screenrec needs to finalise the container or you get an unplayable file.
  • Pause is SIGSTOP/SIGCONT. Worth knowing: this freezes the video timeline, so the output is shorter than wall-clock. If that is confusing, cutting Pause is fine.
  • backend exists so wf-recorder works if you change your mind; the command builder is one small function per backend.
  • Panel closes before slurp runs, same as the screenshot widget.
One install needed: paru -S wl-screenrec. Everything else in this document runs on what you already have. Say the word and I will add it to the plan as an explicit prerequisite step rather than installing it quietly.

What this costs

New files
  • Widgets/AiUsage/ — widget, panel, Services/AiUsage.qml
  • Widgets/ScreenTime/ — widget, panel, Services/ScreenTime.qml
  • Widgets/Ip/ — widget, panel, Services/NetAddresses.qml
  • Widgets/Capture/ — screenshot + recorder, shared Services/Capture.qml
  • Widgets/Calendar/WorldClock.qml
  • Registration in Components/Section.qml, docs in README.md
Constraints held
  • No daemon. Every widget is qsbar's own process reading files, sockets it already holds, or short-lived commands.
  • No network, except none at all — you chose local-only IP and the AI numbers come from disk.
  • One new package: wl-screenrec.
  • State goes to state.json / screentime.json, never to hand-edited config.json.
Suggested order
  • 1. World clock — smallest, touches one existing panel.
  • 2. IP — no new patterns, proves the panel-row-copy idiom.
  • 3. Screenshot — establishes the capture service.
  • 4. Recorder — reuses it, adds process lifecycle.
  • 5. Screen time — needs idle detection and persistence.
  • 6. AI usage — the largest, four parsers plus a rollup cache.
